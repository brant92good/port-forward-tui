# Ports 0.9.0

Saved forwards are easier to scan and edit: names lead each row, servers have
their own group headings, and **E** includes the **Open automatically** checkbox.
F2 and CLI preferences still work. Changing only that checkbox leaves the current
connection alone and applies when a new view opens.

The screen writer now batches output at draw boundaries. Controlled Windows
ConPTY measurements delivered the same frame bytes with far fewer writes; see
[the measurement and its limits](https://github.com/brant92good/port-forward-tui/blob/v0.9.0/docs/rendering.md). This is not a network-speed
or desktop-hotkey claim.

For a running web app, **T** previews the HTML title from its local HTTP address.
**U** uses it in this view; **Enter** keeps your saved name. No favorite is
renamed, and no check runs automatically. The bounded reader does not follow
redirects, authenticate, use HTTPS or run JavaScript.

This prerelease includes Windows x64, Linux x64/ARM64 and macOS
Intel/Apple Silicon (**beta**) builds. The release workflow publishes after all
five native build and package checks pass, then tests the actual HTTPS downloads.
Check the [workflow run](https://github.com/brant92good/port-forward-tui/actions/workflows/native.yml)
for those final installer results; macOS desktop use remains beta.

Bundles include the application license and third-party notices, validated with
the binaries. Install from the [README](https://github.com/brant92good/port-forward-tui/blob/v0.9.0/README.md#install), then choose or
import an SSH machine. Normal use needs OpenSSH, without Python or Cargo.
