# Ports 0.10.0-beta.4: experimental voice forwarding

Save SSH forwards and SOCKS5 proxies across servers, keep them running in the
background, and try optional voice forwarding from a Windows microphone to Linux.

**Voice is experimental, optional and disabled by default.** The Windows client
uses FFmpeg/FFplay and an already prepared compatible Linux audio bridge. The
Linux endpoint and media tools are not bundled. No specific agent voice mode is
claimed compatible; this is not a complete remote voice installer.

- V opens the experimental audio panel; the main view shows its current state.
- Enter explicitly starts microphone/reply streaming; S in that panel stops it.
- Opening Ports, reconnecting a forward or opting into automatic port opening
  never starts the microphone. There is no automatic recording retry.
- Windows uses binary PCM pipes and owns its media/SSH children; stopping asks
  the remote bridge to restore its previous audio defaults. The panel reports
  unconfirmed restoration if a connection failure prevents verification.
- Linux/macOS show that microphone capture needs a Windows client. Their fixed
  forwards and SOCKS proxies remain available; macOS desktop use remains beta.

This prerelease uses ports-beta, isolated beta metadata and protocol2 controllers.
Stable 0.9.1 remains Latest; its normal installation path is unchanged. Existing
beta1 settings remain usable. Stop a duplicate old forward before opening the
same local port in a different installation. Closing a view leaves ordinary
background forwards running; stop audio explicitly before closing its host.

Qualification is published with release-record.json and per-target receipts.
The release workflow requires native tests, Clippy, installer/package checks and
Linux disposable OpenSSH forwarding tests before publishing assets. Its later
released-install jobs check actual HTTPS downloads on all five targets. Those
checks do not establish physical microphone/playback or agent voice compatibility.
Historical Windows/Linux transport observations are in docs/audio.md; beta4 adds
explicit experimental labels and unsupported-platform guidance.
